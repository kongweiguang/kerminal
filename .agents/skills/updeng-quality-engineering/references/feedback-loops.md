# 诊断反馈回路

## 选择回路

| 类型 | 适用场景 | 最低证据 |
| --- | --- | --- |
| 自动化测试 | 本地/CI 可触发代码路径 | 失败测试、命令、正确失败原因 |
| HTTP/CLI | API、鉴权、序列化、批处理 | 固定请求/输入、状态码、输出摘要 |
| 浏览器/桌面自动化 | UI、路由、WebView、平台交互 | DOM/窗口状态、console/network、截图 |
| Trace/日志回放 | 外部系统、复杂事件流 | 脱敏 payload、顺序、关键时间点 |
| 最小 harness | 完整系统过重或入口分散 | 最少依赖、固定输入、明确输出 |
| 压力/随机循环 | 竞态、时序、缓存、偶发失败 | 次数、seed、失败率、首个失败样本 |
| 人工协助 | 真实账号、硬件或生产界面 | 可重复步骤、环境、观察与截图 |

## 质量标准

- 症状准确：失败与用户报告一致。
- 可重复：稳定复现，或有足够失败率与样本。
- 可收窄：能减少输入、依赖或环境差异。
- 可验证修复：同一回路在修复后转绿。
- 可保留：转成测试/脚本；不能保留时说明原因。

## 偶发问题

- 固定时间、时区、随机种子、并发数、缓存目录和网络开关。
- 循环运行并记录分母、失败次数和首个失败输入。
- 通过 barrier/channel 或并行触发扩大竞争窗口，不用任意 sleep 掩盖问题。
- 对比两个版本、配置、机器或数据集；必要时用 `git bisect run` 包装最小检查。

## 临时插桩

- 使用唯一前缀并在收口前全文搜索。
- 只放在能区分假设的边界，不撒网打印。
- 不记录 token、凭据、完整用户内容、生产数据或无限 payload。
- 插桩必须有删除条件；保留的观测点应转为正式、分级且有界的日志/指标。
