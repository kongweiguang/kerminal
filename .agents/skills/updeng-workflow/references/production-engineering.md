# 生产工程边界

只在非 trivial 实现涉及公共契约、复杂状态、外部副作用、性能、启动/运行时或渐进迁移时读取。本参考保存旧版开发治理中仍能改变实现质量的工程不变量，不把某种三层架构、固定文件行数或设计模式当成普遍答案。

## 先定义不变量

开始接线前写清用户/调用方可观察行为，以及必须保持的入口、交互、快捷键、配置、序列化、数据读写、顺序、错误、资源释放和兼容语义。确需改变时同时说明调用方、迁移、兼容窗口、失败信号和回滚。

## 决策与副作用分离

- 复杂判断、状态派生、权限开关、展示策略和边界规则优先进入纯 model/policy/resolver 或项目已有等价边界。
- 文件、网络、数据库、平台 API、外部 SDK、进程、定时器、队列和缓存通过窄 adapter/facade/可注入函数隔离。
- UI、Command、Controller、handler 和 runtime glue 负责输入适配与结果映射，不成为唯一可测试的业务规则位置。
- 只有真实变化点存在时才引入 Strategy、Factory、Command、Presenter 等模式；没有降低耦合或验证成本时保持直接实现。

## 状态与恢复

为并发、重试、取消、超时、重复触发、部分成功、进程退出和恢复定义权威状态与幂等边界。外部副作用要说明创建了什么、何时可见、失败留下什么、谁清理，以及重试是否会重复执行。

数据或 schema 迁移必须有版本源、顺序、事务/检查点、向前与回退策略、旧客户端/旧数据兼容和迁移后验证。无法安全回滚时写明替代恢复方案，不用“revert 代码”冒充数据恢复。

## 性能语义

只优化有基线或明显复杂度热点的路径。修改缓存、批处理、懒加载、队列或并发前，记录必须保持的同步可见性、顺序、回调次数、错误传播、资源上限和释放行为；优化后用同环境、同输入和可重复指标比较。

## 验证层级

| 边界 | 首选证据 |
| --- | --- |
| 纯规则或状态转换 | 行为单测、性质/边界样例 |
| adapter/外部 IO | fake/临时资源 + 失败/取消/清理测试 |
| 公共 API/IPC/序列化 | caller fixture、兼容与非法输入测试 |
| UI/桌面/WebView | 真实 dev/app 启动、关键状态与截图 |
| 性能或资源 | 基线、压力/长稳、上限和释放证据 |
| 发布/迁移 | 目标产物/环境、回读、失败恢复和回滚后复验 |

局部测试绿色不能替代合并后、目标 checkout 和真实入口验证。无法运行时记录具体环境缺口、未覆盖场景和剩余风险。

## 代码卫生

- 所有新增、重写或本轮修改且支持注释的人工维护文件，文件头必须标注 `@author kongweiguang`；仅不支持注释、机器生成、锁文件、vendor、缓存和二进制例外。
- 先找最近似实现和复用点；第二次重复时评估抽取，第三次重复必须说明保留原因。
- 大型或高冲突文件先按真实责任边界拆分，不按固定行数机械切文件，也不借机格式化无关区域。
- 测试 fixture、mock、调试 harness、一次性迁移产物和生产源码分开。
- 注释说明业务原因、危险边界和不明显取舍，不复述代码。
- 完成前清理临时日志、开关、生成物、兼容垫片和过期 fallback；需要保留时写删除条件。

## 委派与集成

任务胶囊至少包含背景、目标、非目标、owned/shared paths、参考、禁止改动、验收、验证和回滚。subagent/worktree 只交付独立切片；主控复读 diff、检查越权、解决共享契约冲突，并在目标 checkout 重跑集成门禁。
