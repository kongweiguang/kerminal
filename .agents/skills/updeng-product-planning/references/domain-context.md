# Updeng 领域上下文

## 真相源

- 先读 `AGENTS.md`、相关代码/测试、API、表/事件/权限标识和现有 `.updeng/docs/business/`。
- 有 `.codegraph/` 时先查询概念入口与调用路径；否则用 `rg` 查真实用法。
- 已由当前代码实现并验证的共享语言写入 `.updeng/docs/business/<module>/domain-language.md`；尚在讨论的术语、状态设计和候选边界写入对应 discovery 模块。结构参考 [context-document.md](references/context-document.md)。
- 技术取舍跟随 discovery 和当前 plan；只有已经实现的外部字段语义才写入 `.updeng/docs/integrations/<module>/`，不要复制。

## 工作方法

1. 列出冲突词、候选含义、代码证据、使用角色和会改变的行为。
2. 能从仓库确认的先自行确认；只向用户询问业务拥有者才能决定的语义。
3. 每次提出一个具体冲突，并说明推荐含义以及它会改变的接口、状态、数据或测试。
4. 用户确认后立即更新最小拥有文档，其他位置只链接，不维护第二份定义。

每个稳定术语至少包含：首选名称、简明定义、包含/不包含、同义词或禁用词、关键状态/约束、代码标识和一个反例。不要把临时实现步骤或调研笔记写入词汇文档。

## 收口

报告已确认术语、仍需业务决定的问题，以及对接口命名、测试、issue 切片和文档的影响。长期技术选择和产品拆分继续使用 `updeng-product-planning` 的对应工作面。
