# 技术决策记录

## 比较维度

| 维度 | 必须回答的问题 |
| --- | --- |
| 当前约束 | 目标用户、调用方、运行时、平台、数据、权限和团队工具链是什么 |
| 可维护性 | 是否减少状态/依赖复杂度，是否更容易测试、诊断和替换 |
| 安全与隐私 | 是否扩大权限、secret、网络、供应链或数据泄漏面 |
| 兼容 | 对 API、schema、配置、已安装客户端和历史数据有什么影响 |
| 性能与资源 | 启动、延迟、吞吐、内存、磁盘、包体和构建成本是什么 |
| 运营成本 | 许可证、云资源、发布、监控、值守和学习成本是什么 |
| 可逆性 | 如何试点、何时退出、怎样回滚或被下一决策替代 |
| 证据 | 仓库事实、原型、基准、官方资料和反例分别支持什么 |

不要用流行度代替适配性，也不要复制整段调研。只保存会改变决定的证据和限制。


## 生命周期

尚未实现的记录保留在对应 discovery 模块。实施时由 plan 引用，并在 `operations.jsonl` 留下采用或改变决定的短事件。实现后只把当前真实行为提炼到 business/integrations；历史记录继续保留取舍原因。

决定改变时新写替代关系或追加明确修订，不静默覆盖旧理由。若新证据只影响实现细节而不改变长期取舍，更新 plan 即可，不制造决策文档。
