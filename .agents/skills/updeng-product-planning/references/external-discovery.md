# 外部发现模板

## 何时必须做

复杂需求、产品形态不清、设计未知、选型、公共契约、数据模型、权限安全、长期架构或用户主流程变化，默认先做外部发现。

可以跳过的情况只有：用户禁止联网、任务涉密、网络不可用、明确小修、外部事实与方案无关。跳过时必须写明原因。

## 搜索顺序

1. 官方文档或标准：确认术语、约束、限制和安全边界。
2. 成熟产品或竞品：观察主流程、信息架构、边界行为和用户可见取舍。
3. GitHub 成熟项目：看维护活跃度、release、README、examples、tests、issue 和 PR。
4. 反例和常见坑：看 FAQ、migration guide、security note、踩坑 issue。

## 产物格式

```markdown
## 外部发现

| 来源 | 类型 | 成熟度/可信度信号 | 可借鉴点 | 不采用/风险 | 链接 |
| --- | --- | --- | --- | --- | --- |

## 发现结论

- 采用：
- 不采用：
- 影响的需求/验收：
- 跳过原因：
```

## 质量门槛

- 至少覆盖官方资料和一个成熟参考；确实找不到时说明检索词和原因。
- GitHub 参考必须说明维护信号，不只看 star。
- 只记录会影响需求、验收、架构或风险的证据，不复制长文。
- 后续 PRD、ADR、plan 只引用发现结论，不重复调研过程。
